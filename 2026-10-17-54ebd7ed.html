1면 · 테슬라 로드스터 6개 출처행사 10/16(금) 09:55 KST (10/15 19:55 CT)

「로켓을 실었던 로드스터,
이제 로드스터에 로켓을」

테슬라가 새 를 생중계로 공개했습니다. 버전은 Performance·Thrust·Rocket 3가지이고, 맨 위 Rocket은 차체 둘레의 가스 분사 장치로 떠오를 수 있다고 테슬라가 밝혔습니다.

현재 상황공개 직후 테슬라는 공식 X에 사양을 올렸습니다. 주행거리 약 483km(300마일) 이상, 최고 속도 약 370km/h(230mph) 이상(Rocket)이고, 정지에서 약 97km/h(60mph)까지 Performance 1.6초 미만, Thrust 0.9초 미만, Rocket 0.59초 미만입니다. 공식 페이지에서 예약을 받기 시작했습니다.

왜 중요한가테슬라와 스페이스X 기술이 한 차에 처음 합쳐졌습니다. 우주선 자세를 바꿀 때 쓰는 를 차에 넣었고, 날개를 움직이는 장치는 테슬라 로봇 의 구동 장치(액추에이터)를 썼다고 테슬라가 밝혔습니다. 머스크 회사들의 부품이 서로 섞이는 모습입니다.

배경차 안의 빈 공간마다 를 채웠고, 가스가 많을수록 오래 날 수 있다고 합니다. 바닥 공기를 빨아내는 팬 장치는 차를 거꾸로 붙들 만큼의 를 멈춰 있을 때도 만든다고 공식 페이지에 적혀 있습니다. 2018년 스페이스X 로켓에 1세대 로드스터를 실어 우주로 보낸 일이 있어 「로켓을 실었던 차에 이제 로켓을 실었다」는 문구가 나왔습니다.

6개 출처Anthropic · Claude Code

Claude 코드 리뷰 정식 출시 — 「Claude Code 코드의 약 90%는 Claude가 씁니다」

한 줄가 10/16(금) 07:51 KST (10/15 15:51 PT)에 서비스(Code Review)를 Team·Enterprise 요금제에 정식 출시했습니다. 저장소마다 Quick·Standard·Deep 세 단계 깊이를 고를 수 있습니다.

왜 중요한가Claude Code 팀 공식 블로그 글 「How the Claude Code team does code review」(출시와 함께 게시, 현지 날짜 10/15)에 따르면 6~9월 사이 합쳐진 수는 두 배 넘게 늘었는데, 문제가 생겨 비율은 40% 넘게 줄었습니다. AI가 코드를 쏟아내는 시대에 「사람이 한 줄씩 읽는 검토」 대신 「AI가 여러 겹으로 검사하고 사람은 위험한 변경만 본다」로 바꿔 품질을 지켰다는 이야기입니다.

배경여러 가 동시에 버그를 찾고, 다른 에이전트 무리가 투표해 「진짜 버그」만 남깁니다. 위험도는 누가 썼는지가 아니라 변경 내용으로 정합니다. 문서 수정은 자동 검사만 통과하면 사람 승인 없이, 자동 업데이트 같은 민감한 곳은 1명, 가장 위험한 코드는 2명이 승인합니다. AI의 승인은 사람 승인을 대신하지 못합니다. Claude Code를 만든 는 「거의 모든 버그를 합치기 전에 잡아 준다」고 X에 썼습니다.

Boris Cherny @bcherny · 10/17(토) 03:12 KST (10/16 11:12 PT)
“I could not imagine being productive without Claude Code Review. It runs on all of my PRs”
“Claude 코드 리뷰 없이 생산적으로 일하는 건 상상할 수 없습니다. 제 모든 PR에서 돌아갑니다.”

요금추가 과금·크레딧이 서비스(Code Review)는 요금제에 포함된 사용량이 아니라, 토큰 사용량만큼 회사 계정의 사용량 크레딧(usage credits)에서 따로 빠집니다(리뷰 깊이·푸시마다 다시 돌릴지에 따라 비용이 달라짐, 공식 비용 문서). 반면 내 컴퓨터에서 돌리는 /code-review 명령은 구독 사용량모든 요금제에서 쓸 수 있고 평소 Claude Code 사용량에 포함됩니다(공식 문서).

다만공식 문서는 「리뷰는 승인·차단을 하지 않고, 지적이 없다고 코드가 안전하다는 뜻은 아니다」라고 적었습니다.

2개 출처Anthropic · 과학

Claude가 설계한 양자 회로, 기존 최고 기록을 넘다

한 줄Anthropic이 10/17(토) 02:47 KST (10/16 10:47 PT)에 가 화학·최적화·정수론 등 8가지 과제에서 기존 발표된 최고 설계보다 와 게이트를 모두 덜 쓰는 설계를 찾았다고 밝혔습니다. 일부는 10배 이상 좋아졌습니다.

왜 중요한가양자컴퓨터는 아직 큐비트가 적어 쓸모 있는 계산을 못 합니다. 회로가 가벼워지면 같은 기계로 더 일찍 쓸모가 생깁니다. 타원곡선 계산 회로 하나는 사람 개입을 최소로 한 채 53시간 만에 나왔고, 기존 가장 작은 설계보다 큐비트는 12% 더 쓰지만 게이트는 17배 적습니다.

배경 연구로, 하버드대 연구진과 함께했습니다. Claude는 회로를 코드로 쓰고, 채점 프로그램이 맞는지 검사해 점수를 돌려주면 다시 고치는 방식으로 일했습니다.

다만Anthropic은 Claude가 처음엔 익숙한 방법만 고집해, 여러 방법을 동시에 시도하게 하고 가끔 「더 넓게 보라」고 지시해야 했다고 적었습니다. 회로 설계는 양자컴퓨터를 만드는 여러 부분 중 하나일 뿐입니다.

1개 출처Google DeepMind · 에이전트

Gemini 에이전트 4개, 27시간 만에 마인크래프트 끝판 깨

오늘의 팁 — 「실패의 정의 3줄」을 CLAUDE.md에 (REVIEW.md는 유료 서비스용)

무엇이 바뀌었나
  1. Claude 코드 리뷰 정식 출시(Team·Enterprise, 추가 과금·크레딧). 깊이는 Quick·Standard·Deep 중 저장소마다 고름. PR에 @claude review라고 댓글을 달면 다시 검토
  2. Cursor: 클라우드 에이전트가 일하는 중에 대시보드·보고서를 「캔버스」로 만들고 링크로 공유(10/17(토) 05:33 KST (10/16 13:33 PT), Cursor 공식 X)
  3. Cursor: 메타 Muse Wonder 추가(위 「함께 볼 소식」)
오늘 해볼 것
  1. 모두에게: 저장소의 CLAUDE.md에 「이 저장소에서 실패란 무엇인가」를 3줄로 씁니다(예: 문서는 「거짓말하는 것」, 설정은 「잘못 보내는 것」 — Claude Code 팀 블로그 방식). 내 컴퓨터의 /code-review 구독 사용량는 CLAUDE.md만 읽고 REVIEW.md는 읽지 않습니다(공식 문서).
  2. Team·Enterprise에서 Code Review 서비스를 켰다면: PR 리뷰에만 쓸 규칙은 REVIEW.md에 따로 둡니다. 이 파일은 GitHub PR을 보는 관리형 서비스 추가 과금·크레딧만 읽습니다(공식 문서).
  3. 작업을 마치면 /code-review와 /security-review를 내 컴퓨터에서 먼저 돌립니다(모든 요금제, 구독 사용량).
  4. AI끼리 고치고 다시 검토하다 끝없이 돌지 않게 「검토는 3번까지」로 정해 둡니다. 팀 글에는 밤새 50번 넘게 돈 사례가 있습니다.
